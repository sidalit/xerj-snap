# XERJ snap

[![xerj](https://snapcraft.io/xerj/badge.svg)](https://snapcraft.io/xerj)

Snap packaging for [XERJ](https://github.com/xerj-org/xerj), a local search engine and MCP server for code, documents and AI agents.

Unofficial build, not affiliated with or endorsed by the XERJ project.

## Build

```bash
snapcraft pack
```

## Install and try

<a href="https://snapcraft.io/xerj"><img alt="Get it from the Snap Store" src="https://snapcraft.io/en/dark/install.svg" width="180"></a>

```bash
sudo snap install xerj
sudo snap connect xerj:removable-media   # optional: /media, /mnt
xerj --data-dir ~/xerj-data
```

Keep that terminal open. In another terminal, index your project:

```bash
export XERJ_API_KEY="$(cat ~/xerj-data/admin.key)"
xerj autoindex ~/my-project
xerj search "your search terms"
```

The server listens on localhost with authentication enabled. Open the console setup URL printed at startup. Keep its data directory outside the folders you index.

For MCP clients, use command `/snap/bin/xerj`, arguments `["mcp"]`, and environment `XERJ_AUTH="ApiKey <your key>"` against the running server.

## Known limitations

- Files must be in a non-hidden home folder or connected removable storage. Hidden files directly under your home directory are inaccessible.
- Neural embeddings run on the CPU and download model files on first use. Models, corpus caches and settings live under `~/snap/xerj/common`.
- The amd64 build requires an x86-64-v3 CPU, matching upstream's release binaries.
- Replace the binary path in MCP configuration generated by `xerj init` with `/snap/bin/xerj`.
- Host SSH keys, credential helpers, browser launching and GitHub CLI integrations are unavailable. Use HTTPS corpus URLs and open the console URL yourself.

## Update to a new upstream release

Change `source-tag` in `snap/snapcraft.yaml`, then rebuild. The version is taken from the upstream project metadata.

## Automation

Builds, publishing, and dependency updates use [snap-automation](https://github.com/sidalit/snap-automation).
